## Context

`ClipTablePanel` 的填充按钮通过构造参数 `timeline_fill_callback` 拿到一个返回 `(start, end)` 的函数，主窗口传的是 `_timeline_range_from_maya()`（`main_window.py:1230`），内部调 `maya_utils.timeline_range()` 读 `playbackOptions`。

播放范围是视图状态：随手拖过滑块、打开别人的场景、Maya 默认的 1–120，都会让它和真实动画长度对不上。下载的动作资源尤其如此。

已有的抓手：`SkeletonPreset.bone_map` 里 `"pelvis"` 这个键在两个内置预设中都有映射（UE Mannequin → `pelvis`，Mixamo → `Hips`）；`maya_utils.resolve_joint()` 能把短名解析成场景里的长路径，并在同名多个时挑层级最浅的那个。

约束：`ClipTablePanel` 的回调签名不变（返回二元组），改动只落在主窗口那个回调的实现和 `maya_utils` 的新函数上。所有 Maya 调用必须能在无 Maya 环境下安全失败——测试跑在纯 Python 里。

## Goals / Non-Goals

**Goals:**
- 填充给出的区间等于骨骼上真实的关键帧范围。
- hips 优先，因为原地动画的 root 骨骼常常一根 K 帧都没有。
- 定位不到时逐级降级，任何一级失败都不打断用户。
- 无 Maya 环境下不抛异常。

**Non-Goals:**
- 不自动切分多个片段——一次填充只产出一个覆盖全长的片段，怎么切由用户决定。
- 不改时间轴读取函数本身，场景信息栏还要用。
- 不去猜「动画其实从第几帧才真正开始动」——有 K 帧就算数，不做静止帧裁剪。

## Decisions

### 决策 1：读关键帧用 `cmds.keyframe(..., query=True, timeChange=True)`

一次调用拿到全部关键帧时间，取 `min` / `max`。相比 `findKeyframe(which="first"/"last")` 要调两次且需要先设当前时间，这个更直接。

节点列表传入时会自动跳过没有动画的节点，返回 `None` 或空列表——正好用作「这一级没有 K 帧」的判据。

### 决策 2：hips 优先，而不是骨架根优先

用户的场景说明了原因：下载的资源所有骨骼都有 K 帧，但更普遍的情况是原地动画的 `root` 完全没有动画曲线。以 root 为准会漏判成「没有关键帧」，直接掉到最后一级。hips/pelvis 是躯干的承重点，任何有动作的角色它都在动。

定位方式：`preset.bone_map.get("pelvis")` → `maya_utils.resolve_joint()`。自定义预设的 `bone_map` 是空的，自然落到下一级。

### 决策 3：降级链写成一个显式的候选序列

```
hips（预设映射） → 用户选定的骨架根子树 → 场景全部 joint → 时间轴
```

实现成一个「候选节点集合」的列表，逐个尝试取关键帧范围，第一个非空的胜出。每一级都用 try/except 包住——某一级抛异常（节点被删、路径失效）只应跳到下一级，不该炸掉整个填充。

*备选*：只查 hips，查不到就报错让用户去选。否决——填充是个便利功能，卡住用户不如给个次优答案。

### 决策 4：取骨架根时连同子树一起查

用户在导出设置里选的是根关节本身。根可能没有 K 帧而子骨骼有，所以这一级要 `listRelatives(allDescendents=True)` 展开子树再查，否则这一级几乎必然落空，形同虚设。

### 决策 5：帧号取整，不做四舍五入之外的加工

`keyframe` 返回浮点时间。片段的 `start` / `end` 在 schema 里是整数（`Clip.start: int`）。用 `round()` 而不是 `int()` 截断——34.6 帧应该是 35，不是 34。

### 决策 6：按钮文案改为「填充动画范围」

「从时间轴填充」现在是错的描述。新文案不提「时间轴」，避免用户以为它读的还是滑块。

## Risks / Trade-offs

- **同名骨骼解析到错误的那个** → `resolve_joint()` 已有「挑层级最浅」的策略，且这里只影响填充结果的建议值，用户可以直接改表格里的数字。
- **场景里有多套角色时，hips 会命中第一个** → 与现有 `resolve_joint()` 行为一致；多角色场景本就需要用户显式选骨架根，那一级会接住。
- **关键帧含约束/驱动产生的额外帧** → 有 K 帧就算数，符合「导出会 bake 这一段」的预期。
- **降级链让行为变得不那么可预测** → 每一级都有测试覆盖，且实际使用中前两级几乎必然命中。
