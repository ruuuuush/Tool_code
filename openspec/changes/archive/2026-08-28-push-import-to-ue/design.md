## Context

UE 的 Python Remote Execution 是官方能力，由 Python Editor Script Plugin 提供，默认关闭。通信分两段：

1. **发现**：UDP 多播到 `239.0.0.1:6766`，发 `ping`，编辑器回 `pong`（携带节点 id、引擎版本、工程路径）。
2. **执行**：本地开一个 TCP 监听端口，通过多播发 `open_connection` 把地址告诉编辑器，**编辑器主动连回来**，之后在这条 TCP 上收发 `command` / `command_result`。

引擎自带 `remote_execution.py`（`Engine/Plugins/Experimental/PythonScriptPlugin/Content/Python/`），但那个路径随安装位置而变——本机实测在 `E:/UE/UE_5.7/Engine/`，别人机器上又是别处。Maya 端要么去猜引擎目录，要么自己实现协议。

立项前已在本机实测跑通完整链路（mayapy → UE 5.7.4），三条只有实测才知道的事实：

- **只有回环接口收得到 pong**。`0.0.0.0` 和局域网地址 `10.224.71.161` 都收不到，必须把多播出口接口显式设为 `127.0.0.1`。
- **`EvaluateStatement` 只吃单个表达式**。多行导入代码必须用 `ExecuteFile` 模式，否则报 `SyntaxError`。
- **编辑器是反向连接的**。本地必须先监听再发 `open_connection`，顺序反了就永远等不到连接。

## Goals / Non-Goals

**Goals:**
- 导出成功后一键完成 UE 导入，不离开 Maya。
- 零第三方依赖，也不依赖引擎自带脚本的路径。
- 失败必须安静降级到现有的复制代码方式。
- 协议层可在无 Maya、无 UE 的环境下单测。

**Non-Goals:**
- 不启动 UE——只对接已经运行的编辑器。
- 不做跨机器推送（多播 TTL 与防火墙不可控；跨机器仍用复制代码）。
- 不替代交接区的复制代码，那是降级路径也是跨机路径。
- 不自动开启 UE 的远程执行开关——那是用户的工程设置，工具不该偷改。

## Decisions

### 决策 1：自己实现协议，不引用引擎自带的 `remote_execution.py`

协议只有四种消息、一个 JSON 信封，实现量小于"可靠地定位引擎目录"的代码量。自己实现还带来两个好处：Maya 端保持零依赖；协议逻辑可以在纯 Python 下单测，而引擎脚本 import 时就需要 UE 环境。

*备选*：从 pong 返回的 `engine_root` 推出脚本路径再动态加载。否决——发现阶段已经完成了，那时再去加载一个只为发消息的模块，本末倒置。

### 决策 2：多播接口逐个尝试，回环优先

实测表明绑定接口是成败关键，而哪个接口有效取决于机器的网卡配置。做法是枚举本机 IPv4，把 `127.0.0.1` 排在最前，逐个尝试直到收到 pong。

排在最前是因为本地编辑器必然经回环可达，而虚拟网卡/VPN 常常抢走多播，先试它们只是浪费超时时间。

### 决策 3：命令端口动态选择，不写死 6776

实测用的 6776 是官方默认，但那是**编辑器端的默认命令端口**，我们这边是监听方。写死会在多开 Maya 或端口被占时失败。改为 `bind(port=0)` 让系统分配，再把实际端口告诉编辑器。

### 决策 4：整个流程带总超时，且在后台线程执行

发现 3 秒、回连 5 秒、命令 60 秒（导入大 FBX 会慢）。UI 线程不能被这些等待卡住，推送放到 `QThread` 里，完成后通过信号回主线程更新界面。

导入耗时无法预估，所以命令超时给得宽，但必须有上限——没有上限的等待和界面卡死没区别。

### 决策 5：推送执行的代码复用交接区已有的模板

交接区已经生成了填好路径的代码。推送就把同一段文本发过去，不再单独拼一份。两条路径行为一致，模板改动只需改一处。

### 决策 6：失败一律不抛异常，返回结构化结果

`PushResult(ok, message, output)`。UI 只读这三个字段决定显示什么。网络类代码的失败模式太多（超时、拒绝、被防火墙静默丢弃），逐个在 UI 层 catch 只会让调用点变成 try 迷宫。

## Risks / Trade-offs

- **防火墙拦截反向连接** → 监听在 `127.0.0.1`，本机回环通常不受规则限制；仍失败则降级并提示。
- **多个 UE 编辑器同时开着** → 取第一个应答的，并在结果里回显工程名，让用户看得出推给了谁。
- **用户没开远程执行** → 这是最常见的失败，提示语直接给出开启路径，而不是只说"未找到编辑器"。
- **协议版本将来变化** → 消息里带 `version`，收到不匹配的直接丢弃；届时按新版本适配。
- **推送成功但导入本身失败** → 两件事分开报：推送通道成功、导入结果由回传的输出体现。
