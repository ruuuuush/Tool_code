## Context

现在的 `MainWindow._build_ui()` 是一条直线：标题 → 副标题 → 场景条 → 步骤头① → 检查 Splitter → 步骤头② → 片段 GroupBox → 步骤头③ → 导出 GroupBox，全部塞进一个 `QScrollArea`。

三个具体病灶：

1. **标题三重奏**：`StepHeader` + `QGroupBox` + 面板内部 `QLabel` 各说一遍。`main_window.py:79`、`:434` 是面板自带标题，`:847`、`:867`、`:878` 是外层分组框标题，`:840`、`:864`、`:875` 是步骤头。
2. **强制滚动**：`central.setMinimumHeight(1040)` 比默认窗高 880 还大，任何尺寸下都出滚动条。
3. **主色缺席**：`ACCENT = "#e8e6e1"` 是近白色。整套界面没有一个颜色在说「这里是重点」，全靠字重区分，看起来平。

约束：面板类的信号与公开方法被 `_connect_signals()` 和 `tests/test_ui.py` 依赖（`ExportPanel._fbx_dir` / `_ue_root` / `_overwrite` / `_delivery`、`ClipTablePanel.clips()` / `set_clips()`、各 `*_requested` 信号）。这次只动"怎么摆、怎么画"，不动"面板对外是什么"。

## Goals / Non-Goals

**Goals:**
- 三步向导，一屏一件事，默认窗口尺寸下当前步不需要整页滚动。
- 每个内容区只有一个标题；界面上不再有解释性引导语。
- 有明确主色的现代深色视觉，状态用颜色说话。
- 检查门禁可见：导出为什么点不了，界面直接讲。
- 面板对外 API 不变，导出链路零改动。

**Non-Goals:**
- 不改检查项、导出器、manifest 任何逻辑。
- 不改交付卡片的行为（缺 manifest 仍须显示为交付不完整），只重绘。
- 不做多语言切换。
- 不引入第三方 UI 库或图标字体——Maya 内要零依赖启动。

## Decisions

### 决策 1：`QStackedWidget` + 自绘步骤条，不用 `QWizard`

`QWizard` 自带页面模型和按钮栏，但它的外观受平台样式强绑定、在 Maya 里跟 QSS 打架，而且它假设"线性走完就关闭"，与这个工具"反复回到第一步重跑检查"的用法不符。用 `QStackedWidget` 装三页，自己画步骤条，切换自由。

*备选*：`QTabWidget`。否决——Tab 表达"平行的几个视图"，这里是有先后依赖的流程，Tab 会误导。

### 决策 2：标题唯一化——只留步骤条那一层

三层标题里，步骤条那层同时承载"名字 + 序号 + 状态"，信息量最大，留它。删掉面板内部的 `QLabel` 标题（`main_window.py:79`、`:434`）和外层 `QGroupBox` 标题（改用无标题的 `QFrame` 卡片）。

检查那一步是左右分栏（检查树 / 详情），两栏各需一个小标题来区分——这层用轻量的列头样式，不与步骤标题同级，不构成重复。

### 决策 3：主色定为蓝，`ACCENT` 从近白改为 `#4f8cff`

Maya 的界面是中性深灰，蓝色在其中辨识度最高且不刺眼；青绿会和"通过"的状态色撞。

改动连带：`ACCENT_TEXT` 从深色改白色（按钮底色变深了）；新增 `ACCENT_SOFT`（半透明蓝）用于选中行、当前步骤的底色。原来的近白色保留为 `SURFACE_BRIGHT`，仍用于需要高对比的少数元素。

*备选*：保留近白主按钮。否决——用户明确要"一眼看上去好看"，无彩色的界面做不出视觉焦点。

### 决策 4：状态由步骤条承担，`StatusBadge` 退居次要

步骤条的圆点有三态：`done`（主色实心 + 对勾）、`current`（主色描边 + 光晕）、`todo`（灰描边）。检查跑完无 Error 即把第一步置 `done`。这样"我走到哪了、还差什么"在顶部一直可见，不必翻到对应区域去看徽章。

### 决策 5：门禁逻辑集中在一个方法里

新增 `MainWindow._update_gate()`：读当前 `_last_report`，算出能不能导出，然后同时更新导出按钮的 `enabled`、门禁提示文案、步骤条第一步的状态。所有会影响门禁的事件（跑完检查、修复完、切预设、切步骤）都调它，避免状态散落在各个回调里各更新一半。

### 决策 6：去掉 `setMinimumHeight(1040)` 与外层 `QScrollArea`

分步之后每页高度可控，整页滚动没有必要。滚动交给真正需要的内部控件（检查树、片段表自带滚动）。窗口最小尺寸下调到 `860x600`，让工具能停在副屏一角。

### 决策 7：文案删除而非隐藏

`STEP*_HINT`、`APP_SUBTITLE` 直接从 `strings.py` 删掉，不是 `setVisible(False)`。留着的常量下次会被人接回去，而 spec 已经规定界面不承载说明文字。

## Risks / Trade-offs

- **一屏一步会让"边看检查边填片段"变难** → 步骤条支持任意跳转，不强制线性；且片段与检查本就不需要同时可见（检查读的是已填的片段，填完再查）。
- **主色换成蓝色可能与个别 Maya 主题撞色** → 主色只用于主按钮、当前步骤、选中态三处，面积小；其余仍是中性灰。
- **`_build_ui()` 大改，可能碰坏信号连接** → 面板类本身不动，只换容器；`_connect_signals()` 保持原样，改完跑 UI 测试验证。
- **删 `QScrollArea` 后，小窗口下内容可能被压** → 设窗口最小尺寸兜底，并给检查树/片段表设合理的最小高度。
- **测试只能覆盖结构与状态，覆盖不了"好不好看"** → 用离屏渲染出图逐版目测，像上一个 change 那样。
