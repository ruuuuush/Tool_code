## Context

上一版把界面改成了三步向导，但步骤顺序沿用了老的纵向排布：检查在最上面，所以变成了第一步。纵向排布时这不算错——三块内容同屏，用户可以边填边看。拆成分页之后，顺序就成了强制的先后关系，而这个关系是反的。

`_build_context_from_ui()` 组装 `ExportRequest` 时读取：`self._clip_panel.clips()`、`self._export_panel.fbx_path()`、`ue_root()`、`ue_skeleton_path()`、`skeleton_root()`、`include_rig()`。这些全部来自第②③步。检查项里直接消费这些字段的有 7 个，第①步跑检查时它们全是空值。

场景信息栏那侧：`_refresh_scene_info_safe()` 的调用点只有 `_initial_state()` 和 `_on_run_checks()` 末尾。它显示的单位/帧率/轴向正是 `scene.unit`、`scene.fps` 这些检查项的判定依据，却比检查结果还滞后。

约束：面板类（`ClipTablePanel` / `ExportPanel` / `CheckListPanel` / `DetailPanel`）本身不需要改，这次只调装配顺序与状态逻辑。`tests/test_ui.py` 里有一批硬编码索引的导航/门禁测试，必须同步。

## Goals / Non-Goals

**Goals:**
- 顺序改为 片段 → 导出设置 → 检查，让检查拿到完整输入。
- 导出按钮与检查结果同屏，通过即可直接导出。
- 门禁理由只在检查步出现。
- 步骤条反映前两步的填写完成度。
- 场景信息栏自动跟随场景变化，窗口关掉就停。

**Non-Goals:**
- 不强制线性流程——步骤条仍可任意跳转。
- 不改任何检查项的判定逻辑。
- 不改导出器与 manifest。
- 不做「自动跑检查」——检查仍由用户点按钮触发，避免每次改字段都触发一次全场景扫描。

## Decisions

### 决策 1：只换装配顺序，不动面板

`_build_ui()` 里把 `addWidget` 的顺序从「检查页、片段页、导出页」改为「片段页、导出页、检查页」，`STEP_TITLES` 同步调整。面板类本身零改动，信号连接不变。

页索引语义随之变化：`0=片段`、`1=导出设置`、`2=检查`。代码里散落的 `self._pages.count() - 1`（原本指「导出步」）现在指「检查步」，含义正好还是「最后一步」，但为了防止下次再被顺序绊倒，引入常量 `STEP_CLIPS = 0` / `STEP_EXPORT = 1` / `STEP_CHECK = 2`，所有位置改用常量。

*备选*：保留索引硬编码。否决——这次踩的就是「索引隐含语义」的坑，再来一次必然重蹈。

### 决策 2：导出按钮留在导出面板，但检查页也放一个入口

导出按钮是 `ExportPanel` 的一部分（`run_export_requested` 信号从那里发出），把它挪走会破坏面板的自洽。保持按钮在导出面板内，但因为导出设置现在是第②步，用户在第③步检查通过后需要退回一步才能点。

解决方式：底部导航条右侧在检查步显示一个主操作按钮，直接转发 `run_export_requested`。两个按钮共用同一个门禁状态。

*备选*：把导出按钮移到检查页。否决——`ExportPanel` 会变成一个「没有提交动作的表单」，它的 `set_busy()` / `show_delivery()` 都围绕那个按钮组织。

### 决策 3：门禁理由的显示条件从「最后一步」改为「检查步」

`_update_gate()` 里 `on_export_step = self._pages.currentIndex() == self._pages.count() - 1` 改为 `== STEP_CHECK`。语义从「位置」变成「意图」。

同时补一条：前两步的完成度由 `_update_step_progress()` 单独判定，与检查结果无关——片段表非空即第①步完成，三个必填路径齐备即第②步完成。

### 决策 4：场景信息用 QTimer 轮询，1 秒一次，值变才重绘

Maya 没有「单位变了」这种统一信号；`scriptJob` 能监听部分事件（如 `timeUnitChanged`、`linearUnitChanged`），但要为每种属性各注册一个，还要在窗口关闭时逐个 `kill`，漏一个就会在 Maya 里留下指向已销毁窗口的回调。

轮询读的是 `currentUnit` / `currentTime` 这几个纯查询命令，开销可以忽略。缓存上一次的结果，值没变就不碰 QLabel，避免无谓重绘。

定时器 parent 设为窗口本身，随窗口销毁自动停止；同时在 `closeEvent` 里显式 `stop()`。

*备选*：`scriptJob` 监听。记录为后续可选优化——如果 1 秒延迟被嫌慢，再换精确事件。

### 决策 5：刷新失败必须静默降级

轮询在无 Maya 环境（单元测试、纯 Python）会抛 `ImportError`。`_refresh_scene_info_safe()` 已有 try/except 兜底，轮询直接复用它，不额外加逻辑。测试里可以安全地手动触发一次。

## Risks / Trade-offs

- **老用户的肌肉记忆**：习惯了「先检查」的人会不适应 → 步骤条可任意跳转，想先检查仍然点得到；而且原顺序下先检查本来就得回头重跑。
- **1 秒轮询在超大场景中读时间轴是否有成本** → 读的都是 O(1) 的场景属性查询，不遍历 DAG。
- **测试里的步骤索引大面积改动** → 改用常量后，将来再调顺序不必再改测试。
- **检查步多一个导出按钮，可能让人以为有两个不同的导出** → 两个按钮文案一致、门禁状态一致，点哪个都走同一个 `_on_export()`。
